# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## Project

StylesUI is a React 19 component library built with Vite 8 (rolldown), TypeScript, pnpm and oxlint. It must stay fully tree-shakable. Styling uses CSS modules and CSS custom properties only (no Sass, no Tailwind).

## Commands

- `pnpm build`: `vite build` (JS + CSS to `dist/`) then `tsc -p tsconfig.build.json` (declarations only)
- `pnpm typecheck`: `tsc -b` over app and node tsconfigs (includes tests, stories, `.storybook`)
- `pnpm lint`: oxlint
- `pnpm format`: oxfmt (config in `.oxfmtrc.json`); `pnpm format:check` to check without writing
- `pnpm test`: Vitest run once over every project; `pnpm test:unit` (jsdom unit tests) and `pnpm test:storybook` (stories in browser mode) run one side; `pnpm test:watch` to watch
- `pnpm verify`: lint, format check, typecheck and all tests
- `pnpm test:hooks`: `node:test` tests for the Claude Code hook scripts in `.claude/hooks/`
- Single unit test file: `pnpm test:unit src/components/Box/Box.test.tsx`; single test by name: `pnpm test:unit -t "renders a div by default"`; a single story file: `pnpm test:storybook <story file>`
- `pnpm storybook` (port 6006) / `pnpm build-storybook`

A Husky pre-commit hook (`.husky/pre-commit`) runs lint-staged (`.lintstagedrc.json`): `oxlint --fix` then `oxfmt` on staged JS/TS files, `oxfmt` on everything else. `pnpm install` sets it up via the `prepare` script.

The fallow commit gate (see the end of this file) fails on a new file or export that nothing reachable from `src/index.ts` imports (`.fallowrc.json` lists the entry points), so a shared module cannot be committed before its first consumer. Commit them together.

Publishing: `.github/workflows/publish.yml` publishes `@krelborn/stylesui` to npm when a GitHub Release is published, in two jobs. The `build` job, with only `contents: read`, installs, lints, typechecks, tests and builds, then uploads the `pnpm pack` tarball (the same one `pnpm publish` builds) as an artifact. The `publish` job alone can publish: it has `id-token: write` and runs in the `npm` environment, which only `v*` tags can deploy to, and the package's trusted publisher on npmjs.com accepts only this repository, workflow and environment, so no npm token exists. It checks nothing out, installs nothing and runs no project code, only `npm stage publish` on the downloaded tarball, on Node 24, whose npm (11.15 or later) can stage. A staged version goes live only when a maintainer approves it on npmjs.com with 2FA, and npm adds provenance because the repository and package are public. `publishConfig` sends the `@krelborn` scope to npm's registry, even where an `.npmrc` maps it to GitHub Packages, and makes the package public, which a scoped package is not by default. Versions up to 0.8.0 are on GitHub Packages only. Checkout sets `persist-credentials: false`, so install scripts and tests cannot read the token from `.git/config`. Bump `version` in `package.json` first (`pnpm version patch|minor|major`); a published version can't be republished. Prereleases use `-beta.N` versions (not `+N` build metadata, which npm strips) and a GitHub Release marked as a pre-release, which publishes under the `beta` dist-tag instead of `latest`.

Both workflows, `ci.yml` and `publish.yml`, pin every action to a commit SHA with its version in a trailing comment, because a tag can be moved to other code. Dependabot (`.github/dependabot.yml`) checks weekly and opens one PR that moves every outdated action's SHA and comment, taking only versions released at least 7 days before. To pin a new action or upgrade one by hand, look up the tag's SHA with `gh api repos/<owner>/<repo>/commits/<tag> --jq .sha`.

Install dependencies via `pnpm add` without hand-written versions so the latest release is resolved.

## Architecture

- `src/index.ts` is the only package entry. Each component lives in `src/components/<Name>/` (`<Name>.tsx`, `<Name>.module.css`, `<Name>.test.tsx`, `<Name>.stories.tsx`, `index.ts`) and is re-exported from `src/index.ts`.
- `Box` is the polymorphic primitive other components should build on. `as` is constrained to `keyof JSX.IntrinsicElements`, and all other props (including `ref`, React 19 ref-as-prop, no `forwardRef`) are typed from the chosen element via `ComponentPropsWithRef`.
- Polymorphic components take `as` and type their props from it: `Box`, `Card`, `Center`, `Cluster`, `Cover`, `Frame`, `Grid`, `PageLayout`, `Row`, `Sidebar`, `Stack`, `Switcher`, `Text`, `Theme`, `Prose` and `VisuallyHidden`. `Badge` takes `as` too, but only `a`, `button` or `span` (`BadgeElement`). `Field` takes only `div`, `li` or `section` (`FieldElement`).
- Fixed-element components render one element, omit `as` and type their props from it: `Alert` (`div`), `Avatar` and `AvatarGroup` (`span`), `Button`, every icon in `src/components/Icon/` (`svg`), `Code` (`code`), `Counter` (`span`), `Divider` (`hr`), `Fieldset`, `RadioGroup` and `SegmentedControl` (`fieldset`), `Heading` (`h1` to `h6`, from `level`), `IconButton` (`button`), `Kbd` (`kbd`), `Listbox` and `ListboxOption` (`div`), `NavList` (`nav`), `NavListGroup` (`li`), `Popover` (`div`), `Select`, `SkipLink` (`a`), `StatusDot` (`span`), `Tabs`, `TabList` and `TabPanel` (`div`), `Tab` (`button`), `Textarea`, `TextInput` and `Tooltip` (`span`). `Checkbox`, `Radio`, `Segment` and `Switch` render an `input` inside the `label` that names it: `className` and `style` go to the label, `ref` and every other prop to the input. `RadioGroup` omits `role` because it sets `radiogroup` itself. `SegmentedControl` omits `orientation` and always renders a horizontal `RadioGroup`. `Avatar` omits `children`, `dangerouslySetInnerHTML` and `role`, because it is always an image whose content it draws. `AvatarGroup` omits `role` and requires `aria-label` or `aria-labelledby`. `Counter` renders a `Badge` and omits `children`, since it shows `count`. `IconButton` renders a `Button` followed by its `Tooltip`. It requires `label`, which is both the tooltip's text and the button's name, and `children`, the icon. It omits `aria-label` and `aria-labelledby` from `Button`'s props and types them `never`, so a JSX attribute is rejected, because `label` names the button. `StatusDot` omits `children`, `role`, `aria-hidden`, `aria-label` and `aria-labelledby` (the last three typed `never`, so a JSX attribute is rejected), because its `label` decides: with one it is an `img` named by it, without one, or with an empty one, it is `aria-hidden`. Icons take `IconProps`, which omits `as`, `children`, `dangerouslySetInnerHTML`, `role`, `viewBox`, `width`, `height` and the paint props (`fill`, `stroke`, `strokeLinecap`, `strokeLinejoin` and `strokeWidth`), because an icon draws its own artwork 1em square in `currentColor` at the weight `--sui-icon-stroke-width` sets, so `font-size` sizes it, and types `aria-hidden`, `aria-label` and `aria-labelledby` `never`, because its `label` decides them as `StatusDot`'s does. `TabList` requires `aria-label` or `aria-labelledby` and omits `aria-orientation` and `role`. `Tab` omits `id`, `role`, `type`, `tabIndex`, `aria-controls`, `aria-selected` and `aria-disabled`, which the tab pattern sets, and `hidden` and `inert`, because a hidden selected tab would leave the tab list without a tab stop, and its `disabled` sets `aria-disabled` rather than the native attribute, so a disabled tab stays reachable with the arrow keys. `TabPanel` omits `id`, `role`, `hidden` and `aria-labelledby`. A `Tab`'s `aria-controls` points at the `TabPanel` with the same `value`, so every `Tab` needs one. `Tooltip` also omits `popover`, `ref` and `role`, and requires the props `useTooltip`'s `getOverlayProps()` returns. `Popover` omits `popover` and `ref` and requires the props `usePopover`'s `getOverlayProps()` returns, as `Tooltip` does. `NavList` omits `as` and `dangerouslySetInnerHTML` and requires `aria-label` or `aria-labelledby`: it renders a `nav` holding a `ul`, and its props go to the `nav`. `NavListGroup` renders an `li` holding a muted `xs` `Heading` and a nested `ul` that the heading names with `aria-labelledby`, and its props go to the `li`. It omits `dangerouslySetInnerHTML` and `title` for its own `ReactNode` `title`, and requires `headingLevel`, because only the page's outline knows the level. `Listbox` requires `aria-label` or `aria-labelledby` and omits `aria-activedescendant`, `role` and `tabIndex`, which the listbox pattern sets, and `defaultValue` for its own selection. `ListboxOption` omits `id`, `role`, `tabIndex`, `aria-selected` and `aria-disabled`, and its `disabled` sets `aria-disabled`, so a disabled option stays reachable with the arrow keys.
- `Link` and `NavListItem` are the exceptions to `as` being an element name. `Link`'s `as` is `"a"` or a component that renders an anchor, such as a router's link. Its props are typed from that component, which it renders directly rather than through `Box`. `NavListItem`'s `as` is `"a"`, `"button"` or such a component (`NavListItemElement`), typed the same way, and it renders the element inside an `li`. Every prop but `children` and `trailing` goes to the link or button, not the `li`, and an item with `as="button"` defaults to `type="button"`. It declares `children` as a `ReactNode` label and omits the component's own `children`, so a component whose children are a render function rejects one, and it omits `dangerouslySetInnerHTML`, because the item renders its own label. A component given in `as` does not go through `Box`, so `NavListItem`'s stylesheet sets `box-sizing` itself.
- `Listbox` keeps focus on the `listbox` and points `aria-activedescendant` at the active option, which `useListbox` tracks apart from the selection (`value`, else `defaultValue`). `ListboxContext` hands the state to each `ListboxOption`, read through `useListboxContext`. `renderedOptions` finds the options in the DOM from their `role`, `data-value`, `data-text-value`, `aria-disabled` and text, so an option may sit inside a consumer's own component, and `optionId` builds an option's id from its value, which may hold any characters. An option's `textValue`, the text type-ahead matches, defaults to the text of the elements its `aria-labelledby` names, else its own text. The selection tokens `--sui-listbox-selection`, `--sui-listbox-on-selection`, `--sui-listbox-inactive-selection`, `--sui-listbox-on-inactive-selection` and `--sui-listbox-inactive-selection-bar` are read, never declared, so an ancestor can set them; `docs/design/concepts.md` describes the looks, including the disabled and forced-colours ones. Unit tests pin these behaviours:
  - Only a rendered option becomes active. An active option clears itself as it unmounts, and a newly selected option, or a selected one remounting under a new key, takes over while the listbox has focus, so `aria-activedescendant` never names a missing option, even when one render removes the active option and selects its neighbour. A key pressed with no active option moves from the selected option. When neither is rendered, Down moves to the option now at the index the active option had when it became active and Up to the one before it, clamped to the list, while Home and End still go to the ends.
  - Keyboard moves and focus that no press caused scroll the option with `scrollIntoView({ block: "nearest", container: "nearest" })`, and clicks and taps never scroll. A press flag, set on `pointerdown` and cleared on click, blur and `pointercancel` as `Tab`'s is, stops the focus a press causes from scrolling the list under the pointer. `container` is missing from `lib.dom`, so the hook declares a local extension, and a browser without it ignores the option.
  - Enter calls `onAction` once per press, so a held key does not repeat it, and neither Enter nor a double-click acts on a disabled option. A key pressed with Alt, Ctrl or Meta is left alone, so browser and app shortcuts work. Space joins a type-ahead query whose last character came within 500ms, so labels that share a first word can be told apart, and otherwise selects the active option.
- Internal components (`TextControl`, `ChoiceControl`, `RequiredIndicator`, `HorizontalFlow`, `Overlay`, `Spinner`, `Icon` inside `Icon/`, and `AlertIcon` inside `Alert/`) are not exported from `src/index.ts` and have no stories or tests of their own; the public components built on them cover them. `TextControl` (behind `TextInput`, `Textarea` and `Select`) and `ChoiceControl` (behind `Checkbox`, `Switch` and `Radio`) each own the one CSS module their wrappers share, so the wrappers have none. `Spinner` (behind a busy `Button`) is a rotating arc in `currentColor` that is hidden from assistive technology; `Button`'s stylesheet places it and gives it the button's text colour, because the busy label is transparent. `Icon` (behind every icon) renders the `svg`, 1em square on a 24 by 24 `viewBox`, inline-block and stroked in `currentColor`, and owns the one CSS module the icons share.
- Each icon is its own component in `src/components/Icon/`, named for what it means (`CloseIcon`, not `XIcon`), so a bundle holds only the icons it imports and a theme could draw a meaning differently. Its shapes are copied from the `lucide-static` devDependency, under the licence that follows StylesUI's own in `LICENSE` (not a separate notices file, because tools that collect a bundle's licences, such as Vite's `build.license`, read only `LICENSE` files), and the component renders them itself, so the package is not a runtime dependency. `Icon.test.tsx` imports each icon's Lucide SVG with `?raw` and checks the component draws the same shapes, so a copying mistake or a Lucide upgrade that changes the artwork fails it. An icon that points the way the text runs, such as `SendIcon`, passes `mirrored` to `Icon`, which wraps its shapes in a `g` that flips under `:dir(rtl)`, so the flip composes with a transform the consumer gives the `svg`. `Icon.test.tsx` and `Icon.stories.tsx` cover every icon from one table each, so add a new icon to both, to the barrels and to the jsx-a11y component list.
- `src/forms/` holds what the form components share: the `ControlSize` type (the only one of these exported from `src/index.ts`), `FieldContext`, `RadioGroupContext`, the `useFieldControl` hook that merges a surrounding `Field`'s id, description, invalid, required and disabled state into a control's props, the `useRadioGroupItem` hook `Radio` and `Segment` share to take their name, selection, required and invalid state from a `RadioGroup` and report to its `onValueChange`, and `hasContent`. `Field` provides `FieldContext` (`Fieldset` clears it for its children) and a control reads it only through the hook. `RadioGroup` provides `RadioGroupContext` to its `Radio`s and `Segment`s, and the type of its value is not exported. The `src/forms` barrel exports `useRadioGroupItem` but not its props type.
- Each React context lives alone in its own `.ts` module: form contexts under `src/forms/`, and a compound component's context in that component's folder (`Tabs/TabsContext.ts`), read through a hook beside it (`useTabsContext`). A context is never in a component file and never imported through a component barrel. A control or part can then read a context without pulling the component that provides it into a consumer's bundle.
- `src/overlays/` holds what overlay components share: the `OverlayPlacement` and `OverlayDelay` types (both exported from `src/index.ts`), `useOverlay` (open state, delays, ids, the anchor name and Escape), `anchorNameFor` (the `anchor-name` for an overlay's id), `mergeProps` and `syncPopover`. `useOverlay` serves Tooltip; `usePopover` follows the browser's native `toggle` event instead and, when controlled, shows the popover again from its own effect if the parent keeps `open` true, skipping an element a remount detached. It focuses `initialFocus` on the opening `toggle`. Its closing `beforetoggle` notes whether focus is inside the popover, or lost to the page after a `close()` (WebKit doesn't focus a clicked button), and if so the closing `toggle` moves focus to the trigger, found through its `popovertarget` outside the popover, unless the browser has already returned it somewhere. Each kind of overlay has a public hook (`useTooltip`, `usePopover`) that hands out prop getters, `getTriggerProps()` and `getOverlayProps()`, which merge the consumer's props with the hook's through `mergeProps`. `mergeProps` keeps both `anchorName`s when both set dashed idents, so one trigger can anchor a tooltip and a popover, as an `IconButton` does; a consumer's keyword, such as `none` or `inherit`, gives way to the hook's name. Overlays render in place in the DOM, as `popover="manual"` (Tooltip) or `popover="auto"` (Popover), and are positioned with CSS anchor positioning, so they keep the theme around them. The internal `Overlay` (behind `Tooltip` and `Popover`) renders a `span` or a `div`, and shows or hides itself when `open` changes, checking `:popover-open` first, so a re-render never undoes an opening or closing the browser made before its `toggle` event updates `open`. The browser refuses to show a popover while it shows or hides another, and returns focus to a popover's trigger before it has finished closing the popover, so `useTooltip` waits a task before showing a tooltip whose trigger got focus back that way, and `syncPopover`, which `Overlay` and `usePopover`'s re-show effect call, retries a refused call on the next task, from a timer, unless the popover has left the document, so a second refusal is reported as a `PopoverRefusedError` without unmounting the app. Only an `InvalidStateError` counts as a refusal; any other error is thrown during the commit. `Overlay` owns the popover and positioning styles: it resets the browser's popover defaults in a zero-specificity `:where()`, so the component built on it owns its look, and its placement rules sit outside the `:where()`. `src/components/Tooltip/tooltipCoordinator.ts` keeps module-level state (the open tooltip and when the last one closed), so its tests move the fake clock an hour per test.
- `src/accessibility/` holds `RequiredAccessibleName`, the union type that makes a landmark or widget require `aria-label` or `aria-labelledby`, and `idSegment`, which turns any value (unpaired surrogates included) into id-safe text, so `Tab`, `TabPanel` and `ListboxOption` ids cannot collide or throw. Neither is exported from `src/index.ts`.
- `src/collections/` holds the keyboard logic collections share: `targetIndexForKey` maps an arrow key, Home or End to the item it moves to, for a horizontal or vertical collection, in either writing direction, wrapping or not. It also holds type-ahead: `extendTypeAheadQuery` adds a typed character to the query, starting a new one when the last character came more than 500ms before, `isTypeAheadQueryLive` says whether a query's last character came within those 500ms, and `typeAheadTarget` finds the first item from the current one on whose text, trimmed, starts with the query, ignoring case and wrapping round. A one-character query, counted in code points, starts after the current item, so a character typed again once the query has reset moves on, and longer text starts at the current item itself, so it keeps matching while it can. Its barrel exports the four functions with the `WritingDirection` and `TypeAheadQuery` types, and none of them is exported from `src/index.ts`. `Tab` reads the writing direction from `dir` through `:dir(rtl)`.
- `src/errors/` holds `MissingContextError`, which a compound component's part throws when it renders outside the component that provides its state (`Tab`, `TabList` and `TabPanel` outside `Tabs`, and `ListboxOption` outside `Listbox`), and `PopoverRefusedError`, which `syncPopover` throws when the browser refuses to show or hide a popover twice, naming its id, with the browser's error as `cause`. Neither is exported from `src/index.ts`.
- Components read CSS custom properties with fallbacks (e.g. `var(--sui-space-2, 0.5rem)`) so consumers theme by overriding variables. A component's `--_sui-` properties are private, values its stylesheet derives or sets for a state, such as ChoiceControl's indent and halo colours, and consumers override only the `--sui-` ones.
- Global styles live in `src/styles/` (ramps, tokens, `themes/`, `palettes/`, modes, reset) and are built to `dist/styles.css`, exported as `@krelborn/stylesui/styles.css`. Palettes set the semantic colours with `light-dark()`, and themes set every other semantic token. Each theme has a companion palette whose colours it takes at zero specificity (`:where()`), so `data-sui-palette` on the same element or inside overrides them. `tokens.css` derives `--sui-color-control-border`, `--sui-color-shadow` and `--sui-shadow-sm` from palette inputs (`--sui-color-ink`, `--sui-color-shadow-soft`, `--sui-color-shadow-hard`) and theme inputs (`--sui-control-outline`, `--sui-shadow-hardness`, `--sui-shadow-sm-offset`), declared on every theme and palette element so an island of either recomputes them. `docs/design/concepts.md` describes the token tiers and `docs/design/palettes.md` the palette design. `src/styles/themeTokens.test.ts` checks that every theme declares the same tokens and no colour, and that every palette declares the same colour tokens; `--_sui-*` properties are private helpers of one palette and exempt. `paletteNames` in `src/styles/tokenSource.ts` lists the palettes for the token tests, the Contrast stories and the Storybook toolbar, and a type check keeps it equal to `PaletteName`.
- The React Compiler runs at build time (`@rolldown/plugin-babel` + `reactCompilerPreset`), so output imports `react/compiler-runtime`. Don't add manual `useMemo`/`useCallback` for memoization.

### Tree-shaking and CSS delivery (`vite.config.ts`, `package.json`)

These pieces work together; changing one can silently break consumers:

- `preserveModules` + `preserveModulesRoot: 'src'` emit one file per source module; React and `clsx` (`/^(react(-dom)?|clsx)($|\/)/`) are external.
- `vite-plugin-lib-inject-css` adds `import './X.css'` to each emitted chunk, so consumers only get CSS for components they import.
- `assetFileNames` strips `.module` from emitted CSS. If the file were published as `X.module.css`, the consumer's bundler would reprocess it as a side-effect-free CSS module and tree-shake the styles away.
- `"sideEffects": ["**/*.css"]` in `package.json` lets bundlers drop unused JS while keeping CSS imports. Component modules must not have other top-level side effects.
- Scoped class names are `sui-[local]-[hash:base64:5]`.
- `build.cssTarget` is pinned to the `light-dark()` support floor (Chrome/Edge 123, Firefox 120, Safari 17.5). A lower target makes lightningcss rewrite `light-dark()` into fallback variables, which breaks theme and mode nesting. `.storybook/main.ts` reuses the same target through `viteFinal`, and consumers must match it (the README documents this). Anchor positioning and `@starting-style` pass through lightningcss unchanged at this target.
- `fonts/playful.css` lives outside `src/` and is published unbuilt through `files` and `exports`, because library mode inlines every asset and would base64 each font subset. The consumer's bundler resolves its `@fontsource-variable/*` imports, so those packages are `dependencies`.

To verify tree-shaking after build changes, build a throwaway consumer app that imports the package with and without using a component, and check the unused case contains no component JS/CSS.

## Testing

Vitest with jsdom, Testing Library and `@testing-library/jest-dom` matchers. Globals are off (import `describe`/`it`/`expect`/`vi` explicitly), so `src/test/setup.ts` registers Testing Library's `cleanup` in `afterEach`. jsdom has no Popover API, so the same file stubs `showPopover`/`hidePopover`, makes a shown popover visible and reads `:popover-open` as the attribute the stubs set, and it stubs a global `jest` so Testing Library can advance Vitest's fake timers. It also stubs `scrollIntoView`, which jsdom lacks, as a no-op that tests spy on. `rejectInvalidShowPopover()` (`src/test/rejectInvalidShowPopover.ts`) makes `showPopover` throw, until the test finishes, on a popover that is detached or already showing, so a test fails on a needless or late show. jsdom's `:focus-visible` returns false when Tab moves from one element that matched it to another, so tabbing along a row of tooltip triggers is tested in a story, not a unit test. Type-level expectations use `// @ts-expect-error` inside tests and are enforced by `pnpm typecheck`.

Vitest has a `unit` project (jsdom, `src/**/*.test.{ts,tsx}`) and four `storybook-<mode>-<theme>` projects (defined in `vite.config.ts`) that run every story in headless Chromium through `@storybook/addon-vitest`, once per light/dark mode and default/playful theme. Each run executes the story's play function and an axe check limited to WCAG 2.0/2.1/2.2 A and AA rules. Playwright's Chromium must be installed (`pnpm exec playwright install chromium`). The storybook projects set `fileParallelism: false`: with a page per file in each of the four browsers, Chromium answered the trusted input commands so slowly that stories using them timed out, and one file at a time per project runs no slower. Their Playwright `actionTimeout` sits below the test timeout, so a stalled command fails with Playwright's call log. Chromium is the only browser the story tests run in (`instances` in `vite.config.ts`), so Firefox and Safari rendering is covered by no test. Chromium closes a popover on Escape or a click outside, and applies `:active`, only for trusted input. Stories get real input from `trustedInput()` in `src/test/trustedInput.ts`, backed by the `pressKey`, `clickPageCorner`, `clickByTestId`, `hoverByTestId`, `holdPointerByTestId` and `releasePointer` browser commands in `vite.config.ts` (`clickPageCorner` clicks the bottom-right corner of the story's frame, outside what the story renders, `clickByTestId` clicks the element with the given `data-testid`, `hoverByTestId` moves the pointer over that element, so it matches `:hover`, and `holdPointerByTestId` holds the primary button down over it, so it matches `:active` until `releasePointer`). It returns null in Storybook's own UI, so a story returns before the steps that need it. After a trusted click or press, `userEvent.tab()` in a later story no longer gives its target `:focus-visible`, so a story that asserts `:focus-visible` after another story's trusted click or press starts with a trusted key press (`pressKey("Shift")`).

`focusRingContrast` (`src/test/colorContrast.ts`) measures a ring outside the element (a positive `outline-offset`) against the background behind the element. A ring touching the element's edge (an offset of 0) or wholly inside it (an offset of at most minus the outline width) is measured against both the element's own background and the one behind it, and the lower ratio is returned, so nothing inside the element may cover an inset ring. It throws for an element with no drawn outline, for a ring that straddles the edge, and for the browser's default ring (`outline-style: auto`), whose colours it cannot read, so a component that loses its ring rule fails rather than passing on the default.

`isSameColor(element, first, second)` (in the same file) tells whether two colours resolve to the same 8-bit colour in an element's scope, whatever syntax the browser reports each in, such as a `color-mix()` result against a ramp step.

`src/test/choiceControl.ts` holds what the Checkbox, Radio, Switch and palette showcase stories measure. `expectOnSpaceScale` checks a box against the space tokens and the label's letters, and every line of its text against an indent, in either writing direction. The box's width and the indent default to a Checkbox's `--sui-space-4` and `--sui-space-6`, and Switch stories pass `--sui-space-6` and `--sui-space-8`. `expectCentredTarget` checks a label is at least 24px tall with its line in the middle, `textStart` finds where text starts, and `resolvedLength` resolves a length such as a space token in an element's scope. `expectHaloStates` checks that hovering a disabled control shows no halo, then drives real hover and press over a checked and an unchecked one, reading the halo from each input's `box-shadow`, `expectHaloHiddenUnderFocus` checks that keyboard focus hides a hovered halo at once, and `expectDistinctDeclaredHalos` checks the colours an input declares. An element appended inside an `input` gets no computed style, so a colour an input declares is resolved on its label.

## Accessibility

- oxlint's `jsx-a11y` plugin is enabled with the fixed-element components mapped to the element they render (`settings.jsx-a11y.components` in `.oxlintrc.json`: `Alert`, `Avatar`, `AvatarGroup`, `Button`, `Checkbox`, `Code`, `Counter`, `Divider`, `Fieldset`, `IconButton`, `Kbd`, `Link`, `Listbox`, `ListboxOption`, `NavList`, `NavListGroup`, `NavListItem`, `Popover`, `Radio`, `RadioGroup`, `Segment`, `SegmentedControl`, `Select`, `SkipLink`, `StatusDot`, `Switch`, `Tab`, `TabList`, `TabPanel`, `Tabs`, `Textarea`, `TextInput`, `Tooltip` and every icon) and `as` read as the rendered element, so rules see through the polymorphic components. Add an entry when adding a fixed-element component. `control-has-associated-label` cannot see that `IconButton`'s `label` names it, so an `IconButton` whose only child is an icon disables that rule on its line, giving the reason. The rule's `labelAttributes` option is not a fix: it would count a `label` attribute as the name of every control, including a native `button`.
- `jsx-a11y/prefer-tag-over-role` rejects a literal role that has a matching HTML element (`img`, `group`, `option`, `listbox`), but not a role chosen by an expression. Where the element cannot be used, disable the rule on that line and give the reason; `Listbox` does because a native `select` cannot hold rich options, and `ListboxOption` because an `option` element cannot hold rich content.
- A `ul` with no markers sets `role="list"`, because WebKit drops its list role. `NavList` and `NavListGroup` set it directly, with `jsx-a11y/no-redundant-roles` disabled on that line. `Stack`, `Grid`, `Switcher` and `HorizontalFlow` get it through `listRole()` (`src/layout/listRole.ts`), which adds it to a `ul` or `ol` that has no `role`.
- `.storybook/preview.tsx` sets `a11y.test: "todo"` globally (violations reported, not failing). A story file whose stories have no violations sets `a11y.test: "error"` in its meta, so new violations fail the test run.
- Interactive components get a `KeyboardInteraction` story whose play function checks tab order, visible focus, keyboard activation and any WAI-ARIA APG keyboard pattern and ARIA state the widget has. Assert `focusRingContrast(element) >= 3` (WCAG 1.4.11) on the focused element, `borderContrast(element) >= 3` (WCAG 1.4.11) on a form control's border, and use `textContrast(element, background)` for states axe can't reach, such as hover (WCAG 1.4.3). `fillContrast(element, first, second)` compares two fills an element shows, each over the background behind it, so a story can check that rest, hover and press can be told apart, as the ghost Button's does on the page and on a surface; `distinctFillContrast` (1.1) is the lowest ratio that reads as a change of state. All four live in `src/test/colorContrast.ts`, and the four storybook projects cover every mode and theme.
- Draw the focus ring on the element that holds focus, and assert it there: the `input` inside a `Checkbox`, `Switch`, `Radio` or `Segment`, not the `label` around it. A `Listbox` holds focus and draws its ring inside its own edge, and an active option that is not selected draws an inset ring of its own, so assert `focusRingContrast` on each.
- `userEvent.tab()` from `storybook/test` (Testing Library's user-event) only treats a radio group as one tab stop when one of its radios is checked; with none checked it stops at every radio. Start a `RadioGroup` story with a `defaultValue` when it tests tab order.
- `src/styles/Contrast.stories.tsx` asserts every semantic colour pairing a palette guarantees (text 4.5:1, focus ring 3:1, form control border 3:1), once per palette in its own `Theme` island, in every mode and theme, including the focus ring on the `secondary-subtle` tint a hovered `Listbox` option takes. When a component starts relying on a new pairing, add it there.
- Every token read has a literal fallback (`var(--sui-color-text, #111827)`), and every story loads `styles.css`, so no test renders a fallback colour. Check each fallback colour pair for contrast by hand.
- Every interactive target is at least 24px in both dimensions, or spaced to pass axe's `target-size` rule (WCAG 2.5.8), which runs on every story.

## Storybook

Storybook 10 with `@storybook/react-vite`, configured manually in `.storybook/` (globs `src/**/*.mdx` and `src/**/*.stories.tsx`). Import `Meta`/`StoryObj` from `@storybook/react-vite` and `fn` from `storybook/test`.

### Docs

`@storybook/addon-docs` generates a Docs page for every story file (`tags: ["autodocs"]` in `.storybook/preview.tsx`):

- The component's JSDoc is the page description; `src/docs/componentDescription.ts` renders its `@example` tags as code blocks. Prop JSDoc and defaults fill the prop table, and each story export's JSDoc is shown above that story, so give every story one.
- Prop tables come from react-docgen, since the TypeScript-based extractors need the TypeScript JS API that TypeScript 7 lacks. It can't see props inherited from `Box` or substitute generic type parameters, so polymorphic components spell out `OwnProps & Omit<BoxProps<E>, keyof OwnProps>` instead of `PolymorphicProps<E, OwnProps>`, and stories add `argTypes` for inherited props they document (`asArgType`/`childrenArgType` in `src/docs/argTypes.ts`). The story file of a component that requires `aria-label` or `aria-labelledby` spreads `accessibleNameArgTypes` from the same file, since react-docgen can't see those two props through the `RequiredAccessibleName` union.
- Guides are standalone MDX pages in `src/docs/` (`<Meta title="Guides/..." />`), with sidebar order set by `options.storySort`. Embed stories with `<Canvas of={...} />` rather than duplicating examples. MDX files and docs pages don't run in the Vitest storybook projects.
- Don't embed with `<Canvas>` a story rendered in an iframe (`docs: { story: { inline: false } }`) whose play function moves focus: it scrolls the docs page to the focused element and takes focus as the page opens. Link to it instead, as the Forms guide does for the contact form example.
- This Storybook has no `remark-gfm` (`.storybook/main.ts` sets no MDX plugins), so MDX tables render as raw text. Guides use lists.
- On a docs page, `ThemeDocsContainer` keeps the document light, default and Bright to match Storybook's docs UI, and `ThemeRoot` renders each story in a `Theme` island carrying the toolbar's theme, palette and mode. The palette toolbar's `theme` item removes `data-sui-palette`, so each theme shows in its companion palette.

## Coding standards

`docs/standards/` holds the coding standards. `.claude/standards.json` maps each document to the file suffixes it applies to (for example `.tsx` gets comments, typescript and react; `.test.tsx` adds vitest-unit-testing).

The JSX prop order in `docs/standards/react.md` (alphabetical, then `aria-*`, then `data-*`) is enforced by neither oxlint nor oxfmt, so keep it by hand.

Claude Code hooks in `.claude/settings.json` run `.claude/hooks/standards.mjs` so matching standards are in an agent's context whenever it reads, writes or edits a file:

- **PreToolUse (`Read|Write|Edit`)**: adds any matching document not yet in that agent's context, in full. A Write or Edit made before its standards were in context is denied once, with the standards attached, so the change is redone following them. A Write or Edit issued in the same assistant message as the tool call whose hook loaded its standards (matched by `message.id` in the transcript, or loaded under 3 seconds ago when either call is not in the transcript yet) is also denied, without the standards attached, since that other call delivers them.
- **PostToolUse (`Bash`)**: after `git diff`, `git show`, `git log` or `gh pr diff`, adds the standards for existing project files named in the output (raw or rtk-compacted), so diff-based reviews get them too. Output cut short by a pipe such as `| head` may name no files.
- **Per-context tracking**: state lives in `$TMPDIR/claude-standards/<session_id>/<agent_id or main>.json`, so each subagent is tracked separately. A `compact_boundary` entry in the agent's transcript clears its state, so documents are sent again on its next matching tool call.
- **SessionStart (`compact`)**: re-sends every loaded document to the main agent straight after compaction; `clear` resets its state. **SubagentStart (`fork`)**: a fork inherits the main agent's loaded documents.
- **Size limit**: Claude Code moves any single `additionalContext` string over 10,000 characters to a file and leaves only a 2,000-character preview in context, so each event has `slotCount` handlers (`... standards.mjs <mode> <slot>`) that each emit one chunk. Parallel slots share one plan per event via a lock in the state directory. Keep `slotCount` in `standards.json` and the number of handlers in `settings.json` equal; `pnpm test:hooks` checks this.

To add a standard, add the document under `docs/standards/` and a rule in `.claude/standards.json`.

## Specs

`docs/specs/` is where specs live, however they are written: one file per feature, `<YYYY-MM-DD>-<slug>.md`, dated from when the spec was written and listed in `docs/specs/README.md`. A spec a tool writes elsewhere, such as the root `SPEC.md` of the agent-skills `spec-driven-development` workflow, is moved there by the PR that builds the feature, so `main` never has a spec at the root. Plans and task lists, such as that workflow's `tasks/plan.md` and `tasks/todo.md`, are needed only while building, so `tasks/` is gitignored and never committed.

## Fallow local gate

Before any `git commit` or `git push`, run `fallow audit --format json --quiet --explain --gate-marker agent`. If the verdict is `fail`, fix the reported findings before retrying. Treat JSON runtime errors like `{ "error": true, ... }` as non-blocking.

Audit defaults to `gate=new-only`: only findings introduced by the current changeset affect the verdict. Inherited findings on touched files are reported under `attribution` and annotated with `introduced: false`, but do not block the commit. Set `[audit] gate = "all"` in `fallow.toml` to gate every finding in changed files.

For non-skill agents, treat the task map below as the local onboarding source: run the listed fallow command before destructive edits, before commits, and before pull request handoff.
