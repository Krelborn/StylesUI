# Theming

Every component reads its colours, radius, spacing and fonts from `--sui-*` CSS custom properties,
so themes, palettes and modes are pure CSS. `@krelborn/stylesui/styles.css` must be imported once for them to
apply.

## Themes

A theme sets the shape of everything: radius, borders, shadows, spacing, depth, motion and fonts.
StylesUI ships two themes:

- `default`: small radius, thin borders, soft shadows and the system font. Applies to the whole
  page.
- `playful`: a "chunky pop" look made to be fun to use. 2px ink outlines, hard offset shadows,
  roomier spacing and pill buttons that spring up on hover and squash down when pressed.

### Playful fonts

Playful names Fredoka for headings and Nunito for body text, falling back to the system's rounded
font. Import the fonts once, next to `styles.css`, to get the full look:

```tsx
import "@krelborn/stylesui/styles.css";
import "@krelborn/stylesui/fonts/playful.css";
```

The fonts are self-hosted, so the page makes no third-party requests, and they stay out of
`styles.css`, so apps using only `default` never bundle them.

## Palettes

A palette sets every colour. StylesUI ships five:

- `bright`: blue and grey on a white page, with grey cards. For documents, forms and shops.
- `pop`: a cream page in light mode and deep plum in dark, with grape and sunshine-yellow fills.
- `mist`: a cool grey page with white cards, inputs and popovers on it. For web apps, dashboards and
  admin tools.
- `paper`: a warm off-white page with ivory panels and stone greys. For reading, docs and consumer
  apps.
- `dusk`: the dimmest light mode, with nothing near white, and a softer dark mode. For desktop apps
  and long sessions.

Every colour pairing meets WCAG 2.2 AA in every palette, in both modes and both themes.

<Canvas of={PaletteShowcaseStories.AllPalettes} />

Each theme brings its companion palette, Bright for `default` and Pop for `playful`, and `palette`
swaps it. Playful's outlines and hard shadows take the palette's ink, so it keeps its look in any
palette:

<Canvas of={ThemeStories.CompanionPalettes} />

```tsx
<Theme palette="pop" theme="default">...</Theme>
<Theme palette="bright" theme="playful">...</Theme>
```

Set `palette` beside `theme`. A palette set on an outer element does not reach through an inner
`Theme` that sets a theme, because that theme's companion is nearer.

## Motion

Controls in themes with depth, such as playful's buttons, rise on hover and press into their lip
with spring easing. Hover movement only applies on devices that can hover. When the operating
system asks for reduced motion, only colours transition and state changes are instant.

A ghost Button has no lip in any theme: it has nothing to raise, so it changes colour only. Text
inputs, textareas and selects stay flat in every theme, with no lip and no spring. A checkbox, radio
or switch moves its mark with the theme's spring when it is checked.

## Modes

Colour mode follows the operating system by default. `light` and `dark` force a mode, and `system`
goes back to following the OS.

## Switching a subtree

`Theme` sets the theme, palette and mode for everything inside it. They nest independently: an inner
`Theme` can change only the mode and inherit the theme and palette from above.

<Canvas of={ThemeStories.NestedIslands} />

```tsx
<Theme mode="dark" theme="playful">
  <Card>...</Card>
</Theme>
```

`Theme` sets `data-sui-theme`, `data-sui-palette` and `data-sui-mode` attributes, so you can also put
them on any element yourself, for example `<html data-sui-theme="playful" data-sui-mode="dark">`.

## Design tokens

Tokens come in three tiers, and themes and palettes only change the middle one:

1. **Ramps**: colour ramps such as `--sui-blue-600`, shared by every palette.
2. **Semantic**: what a value is for, such as `--sui-color-primary`, `--sui-color-surface`,
   `--sui-radius-md`, `--sui-space-3` and `--sui-font-body`. Palettes set the colours and themes set
   the rest, and components read only these.
3. **Component**: local to a component, such as `--sui-button-bg`. They default to semantic tokens.

[Foundations/Tokens](?path=/docs/foundations-tokens--docs) shows every token in the current theme,
palette and mode.

### Status colours

Each status (`danger`, `success`, `warning` and `info`) has three grades:

- **Fill**: `--sui-color-<status>`, a solid background, and `--sui-color-<status>-hover`, the
  same fill hovered. `--sui-color-on-<status>` is the text on both.
- **Text**: `--sui-color-<status>-text`, for text, borders and icons on the page, on a surface, on
  an overlay and on the status's own subtle.
- **Subtle**: `--sui-color-<status>-subtle`, a tinted background. Body text (`--sui-color-text`)
  sits on it.

`Alert`, a subtle `Badge` and an outlined status `Button` use the text and subtle grades, a solid
`Badge` and a filled status `Button` use the fill, and a form error uses the text grade. Primary-coloured text must not sit on a status
subtle, because it falls below 4.5:1 on some of them.

### Borders

Three tokens draw borders, each for its own purpose:

- `--sui-color-border`: decorative dividers and outlines. It carries no contrast guarantee.
- `--sui-color-control-border`: the outline of `Avatar`, `Button`, `Badge` and a checked checkbox,
  radio or switch. Transparent in `default`, and the palette's ink in `playful`.
- `--sui-color-input-border`: the boundary of form controls, at least 3:1 against the page, a
  surface and an overlay.

### Layers

Five tokens paint the layers of a page:

- `--sui-color-background`: the page.
- `--sui-color-surface`: a panel on the page, such as a `Card`.
- `--sui-color-field`: the fill of a text input, textarea, select, checkbox, radio or switch.
- `--sui-color-overlay`: a layer that floats above the page, such as a `Popover`.
- `--sui-color-sunken`: a recessed chip or block, such as `Code`, `Kbd`, or a code block or table
  header in `Prose`.

Override one to restyle everything on that layer: `--sui-color-field` recolours every form control,
for example, and leaves the page alone, and `--sui-color-background` recolours only the page.

[Foundations/Contrast](?path=/docs/foundations-contrast--docs) checks every pairing each palette
guarantees, in each theme and mode.

## Customising

Override semantic tokens on any element, since components read them directly:

```css
.checkout {
  --sui-color-primary: light-dark(var(--sui-green-600), var(--sui-green-400));
}
```

`--sui-link-color` recolours every link in `Prose` and every `Link` with the default tone inside
the element it is set on. `Alert` sets it so the links inside take the alert's text colour:

```css
.footer {
  --sui-link-color: var(--sui-color-text-muted);
}
```

Base tokens that others are built from only take effect where the tokens built from them resolve:

- Ramp steps, `--sui-space-unit`, the palette inputs `--sui-color-ink`, `--sui-color-shadow-soft`
  and `--sui-color-shadow-hard`, and the theme inputs `--sui-control-outline`,
  `--sui-shadow-hardness` and `--sui-shadow-sm-offset` take effect when overridden on `:root` or on
  an element with `data-sui-theme` or `data-sui-palette`.
- `--sui-radius-md`, which `--sui-radius-control` points at in `default`, takes effect only on
  `:root` or an element with `data-sui-theme`.
