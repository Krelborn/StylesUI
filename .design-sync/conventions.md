# Building with StylesUI

## Setup and theming

- No provider is required. Linking `styles.css` applies the `default` theme with its `bright` palette in `system` colour mode to the whole page (tokens are declared on `:root`), and sets body background, text colour and font.
- To switch theme, palette or mode, wrap a subtree (or the whole app) in `Theme`: `<Theme theme="playful" mode="dark">`. `theme` is `"default" | "playful"` and sets shape (radius, borders, shadows, spacing, motion, fonts); `palette` is `"bright" | "mist" | "paper" | "dusk" | "pop"` and sets every colour; `mode` is `"light" | "dark" | "system"`. Each theme brings its companion palette (`bright` for `default`, `pop` for `playful`) unless `palette` is set beside it: `<Theme palette="mist" theme="default">` is default's look on a cool grey page with white cards, `paper` a warm off-white page, and `dusk` the dimmest light mode. `Theme` renders a `div` that paints its own background and text colour, and themes and palettes can be nested as islands.
- The `playful` theme uses the bundled "Nunito Variable" (body) and "Fredoka Variable" (heading) fonts; `default` uses the system font stack.
- Colours are defined with `light-dark()`, so never hard-code a light or dark colour: use the tokens and both modes work.

## Styling idiom

There are no utility classes. Compose layout with the layout components and their props; style your own elements with the `--sui-*` CSS custom properties via `style` or your own CSS.

- Spacing props (`gap`, `padding`, `gutter`) take a step `0`-`8` on the `--sui-space-1` ... `--sui-space-8` scale, not CSS lengths.
- Most components are polymorphic: pass `as="ul"`, `as="section"` etc. to change the rendered element. These are `Box`, `Card`, `Center`, `Cluster`, `Cover`, `Field`, `Frame`, `Grid`, `PageLayout`, `Prose`, `Row`, `Sidebar`, `Stack`, `Switcher`, `Text`, `Theme` and `VisuallyHidden`. `Badge` takes `as` too, but only `"a"`, `"button"` or `"span"`.
- The rest render a fixed element and take no `as`: `Alert` (`div`), `Avatar` and `AvatarGroup` (`span`), `Button` (`button`), `Code` (`code`), `Counter` (`span`), `Divider` (`hr`), `Fieldset`, `RadioGroup` and `SegmentedControl` (`fieldset`), `Heading` (`h1`-`h6`), `IconButton` (`button`), `Kbd` (`kbd`), `Listbox` and `ListboxOption` (`div`), `NavList` (`nav`), `NavListGroup` (`li`), `Popover` (`div`), `Select`, `SkipLink` (`a`), `StatusDot` (`span`), `Tabs`, `TabList` and `TabPanel` (`div`), `Tab` (`button`), `Textarea`, `TextInput` and `Tooltip` (`span`). `Checkbox`, `Radio`, `Segment` and `Switch` render an `input` inside the `label` that names it: `className` and `style` go to the label, and every other prop to the input. `Link` renders an `a`, or the component given in `as`, such as a router's link.
- All components accept `className`, `style` and the native props of the element they render.
- Layout: `Stack` (vertical, `gap`, `align`), `Row` (horizontal, no wrap by default), `Cluster` (horizontal, wraps), `Grid` (`minimumItemWidth`), `Switcher` (`threshold`), `Sidebar` (`side`, `sideWidth`, `contentMinimumWidth`), `Center` (`width="content" | "prose" | "wide"`, `gutter`, `intrinsic`), `Cover` (`top`, `bottom`, `minimumHeight`), `Frame` (`ratio="16 / 9"`), `PageLayout` (full-height shell; give it `header`, `main`, `footer` children, typically `Center as="main"`).
- Surfaces and controls: `Card` (`padding="sm" | "md" | "lg"`), `Button` (`variant="primary" | "secondary" | "outline" | "ghost"`, `size="sm" | "md" | "lg"`; `ghost` is the quiet toolbar style, flat in every theme, and its hover and press tint whatever is behind it, so it works on a surface; `busy` shows a spinner, keeps the width and the name, and ignores presses, and the spinner is not announced, so pair it with a status message).
- Icon buttons: `<IconButton label="Refresh" onClick={…}><RefreshIcon /></IconButton>` (`label` is required and is both the tooltip and the name; `shortcut="⌘R"` with `aria-keyshortcuts="Meta+R"`; `variant` defaults to `ghost`; `busy`, `size` and `placement` as on Button and Tooltip).
- Icons: `AddIcon`, `ChevronDownIcon`, `CloseIcon`, `DeleteIcon`, `InfoIcon`, `MoreHorizontalIcon`, `MoreVerticalIcon`, `RefreshIcon`, `RemoveIcon` and `SendIcon`. Each is 1em square in `currentColor`, so `font-size` and `color` on it or its parent size and colour it; `--sui-icon-stroke-width` sets the stroke. Without `label` it is decorative and hidden from screen readers; give `label` when the icon alone carries meaning. It takes no `width`, `height`, `fill`, `stroke` or `aria-label`. `SendIcon` mirrors in right-to-left text. Put an icon-only action in an `IconButton`.
- Type: `Heading` (`level` 1-6 is required and sets the element; `size` overrides the visual size, `tone="default" | "muted"` with muted for a quiet label above a group), `Text` (`size`, `weight="regular" | "medium" | "bold"`, `tone="default" | "muted"`; renders a `span` unless `as` is given), `Code` (inline code), `Kbd` (one key per `Kbd`; Prose's raw `kbd` matches it), `Prose` (`size="sm" | "md" | "lg"`, `codeOverflow="wrap" | "scroll"`; `--sui-prose-line-height` loosens its text but not its code; styles the raw `h1`-`h6`, `p`, `a`, `ul`, `ol`, `blockquote`, `code`, `pre`, `img` and `table` elements inside it, for rendered markdown or CMS output).
- Rules and hidden text: `Divider` (`orientation="horizontal" | "vertical"`; a vertical one needs a flex row to stretch), `VisuallyHidden` (text for assistive technology only; for the name of an icon-only button use `IconButton` instead).
- Links: `Link` (`tone="primary" | "inherit"`, `underline="always" | "hover"`; use `hover` for navigation, not running text), `SkipLink` (`href="#main"`; render it first in the page, and give the target the matching `id`). `NavList` (needs `aria-label`) holds `NavListItem`s, optionally inside `NavListGroup`s (`title` and `headingLevel` are required). A `NavListItem` is a link (`href`), a button (`as="button"` with `onClick`, for switching views), or a router link (`as={RouterLink}`). Mark the current one with `aria-current`, and put a `Counter` in `trailing`.
- Lists: `<Listbox aria-label="…" value={id} onValueChange={setId} onAction={open}>` holding `<ListboxOption value={id}>` children (`disabled`; `textValue` for type-ahead, defaulting to the text of the elements `aria-labelledby` names, which can be several, their text joined, else the option's text; name a rich option with `aria-labelledby` and describe it with `aria-describedby`; content outside the elements those two name is not announced, so every element carrying meaning, such as a badge, a count or a labelled `StatusDot`, goes in `aria-describedby`; no interactive content inside). Selection follows the arrow keys, Home, End and type-ahead; Space selects the active option, or joins type-ahead text typed within the last 500ms; Enter or a double-click calls `onAction`. A disabled option is reached but never selected. Muted text and a `StatusDot` inside a selected option take the selection's text colour. Override `--sui-listbox-selection` and `--sui-listbox-on-selection` on an ancestor to change the focused selection colours, and `--sui-listbox-inactive-selection`, `--sui-listbox-on-inactive-selection` and `--sui-listbox-inactive-selection-bar` for the unfocused ones.
- Tabs: `<Tabs defaultValue="a">` (or `value` with `onValueChange`; one is required) holding a `<TabList aria-label="…">` of `<Tab value="a">` and a `<TabPanel value="a">` for every tab, since a tab's `aria-controls` points at its panel. Options: `variant="underline" | "pill"` (pill for switching views in a toolbar), `size="sm" | "md" | "lg"`, `orientation="horizontal" | "vertical"`, `activation="automatic" | "manual"`. `<Tab disabled={true}>` stays reachable with the arrow keys but cannot be selected, and ignores clicks.
- Feedback: `Alert` (`tone="info" | "success" | "warning" | "danger"`, `title`, `icon`; it has no role, so add `role="alert"` for an error raised by an action or `aria-live="polite"` for a quiet update), `Badge` (`tone="neutral" | "primary" | "info" | "success" | "warning" | "danger"`, `variant="subtle" | "solid"`), `Counter` (`count` is required; `max`, `capped`, `hiddenSuffix`, and Badge's `tone` and `variant`; renders nothing below 1), `StatusDot` (`tone`, `variant="solid" | "ring"`, `size="sm" | "md"`, and `label`, without which, or with an empty one, it is decorative; it takes no `aria-label`; `--sui-status-dot-color`, set on a container, recolours the dots inside it, for example to `currentColor` on a row filled with the primary colour).
- People: `Avatar` (`name` is required and names it; `src`, `size="xs" | "sm" | "md" | "lg"`; an empty `src` shows the initials; pass `aria-hidden` when the name is printed beside it) and `AvatarGroup` (needs `aria-label` or `aria-labelledby`; `max` is at least 1 and hides the rest behind "+n", but screen readers still read them; `--sui-avatar-group-ring`, set on a Card to `var(--sui-color-surface)`, recolours the rings, and `--sui-avatar-group-ring-width` sets their width, 2px by default).
- Overlays: `Tooltip` is never rendered on its own. Call `useTooltip()` in your component, spread `getTriggerProps()` on the trigger and `getOverlayProps()` on the `Tooltip`, and render the `Tooltip` right after its trigger. Options are all optional: `placement="top" | "end" | "bottom" | "start"` (default `top`; flips when there's no room), `relationship="description" | "label"` (default `description`; `label` makes the tooltip the name of a trigger with no text of its own, which then needs no other name; for an icon-only button use `IconButton` instead of building this by hand), `delay={{ show, hide }}` in ms, and `open` with `onOpenChange` to control it. It stays in place in the DOM, so it takes the surrounding `Theme`. `Popover` works the same way with `usePopover()`: spread `getTriggerProps()` on a `Button` or `IconButton` and `getOverlayProps()` on the `Popover`, rendered right after the trigger. Options: `placement` (default `bottom`), `defaultOpen`, and `open` with `onOpenChange`; the hook also returns `close()`. It closes on Escape and on a click outside, and only one is open at a time, so never hold two open with `open`.
- Forms: `Field` wraps one control with a `label`, `description`, `error`, `required`, `disabled` and `controlId`, and links them to it. Controls are `TextInput` (`size="sm" | "md" | "lg"`, `type`), `Textarea`, `Select` (native `option` children), `Checkbox`, `Switch` and `Radio` (`value` is required; children are the label). `Fieldset` (`label` is required) groups controls, and `RadioGroup` (`label`, `defaultValue` or `value` with `onValueChange`, `name`, `orientation="vertical" | "horizontal"`, `required`, `error`) groups `Radio`s. `SegmentedControl` (RadioGroup's props without `orientation`, plus `size="sm" | "md" | "lg"`) holds `Segment`s (`value` is required; children are the label), for choosing one of a few short values. A control outside a `Field` needs its own accessible name, such as `aria-label`.

Text on a `primary`, `secondary`, `danger`, `success`, `warning` or `info` background uses the matching `--sui-color-on-*` token; only those pairings have guaranteed contrast in every theme and mode. Status text (`--sui-color-<status>-text`) is for text, borders and icons on the page, a surface or its own `-subtle` background, and `--sui-color-text` also sits on a subtle; primary-coloured text must not sit on a status subtle. `--sui-color-input-border` is the 3:1 boundary of form controls.

`--sui-link-color`, set on an element, recolours every `Link` with the default tone and every link in a `Prose` inside it.

## Where the truth lives

- `styles.css` and `_ds_bundle.css`: every token and theme definition. Read before inventing a colour or size.
- `components/<group>/<Name>/<Name>.prompt.md` and `<Name>.d.ts`: props and examples per component.
- `guidelines/`: the token tiers and theming concepts.

## Example

```jsx
const { Theme, PageLayout, Center, Stack, Row, Card, Heading, Text, Button, Tooltip, useTooltip } = window.StylesUI;

function PublishButton() {
  const tooltip = useTooltip();

  return (
    <>
      <Button {...tooltip.getTriggerProps()}>Publish</Button>
      <Tooltip {...tooltip.getOverlayProps()}>Sends to all subscribers</Tooltip>
    </>
  );
}

<Theme theme="default" mode="light">
  <PageLayout>
    <Center as="header">
      <Text weight="bold">Field Notes</Text>
    </Center>
    <Center as="main">
      <Card padding="lg">
        <Stack gap={3}>
          <Heading level={2}>Project update</Heading>
          <Text tone="muted">The theme system now ships with default and playful themes.</Text>
          <Row gap={2}>
            <PublishButton />
            <Button variant="outline">Dismiss</Button>
          </Row>
        </Stack>
      </Card>
    </Center>
    <Center as="footer">
      <Text tone="muted" style={{ fontSize: "var(--sui-font-size-sm)" }}>
        Written in the open
      </Text>
    </Center>
  </PageLayout>
</Theme>;
```
